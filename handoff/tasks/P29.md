# P29 — Specify a complete finite graph census

**Dependencies:** P03. **Objective:** turn a finite search population into an independently auditable mathematical input set.

**Inspect first:** `scripts/census.py`: `canonical_code`, `connected_representatives`, `census`; `results/small_census.json`; `docs/IMPLEMENTATION.md`; `docs/chapters/12_computational_methodology.md`. The existing baseline enumerates every labeled simple graph through order six, filters connectedness and quotients by degree-respecting permutations. Preserve this useful independent baseline.

**Work:** publish proposed `docs/specifications/CENSUS-v1.md` and a canonical graph manifest with generation options, order range, connectivity convention, labels, edge lists and graph digests. Prove why the degree-block permutation code decides isomorphism within each order; do not confuse a degree sequence filter with that full permutation search. Explain representative selection and separate labeled population counts from isomorphism-class counts. If adding a scalable external generator, pin its version/options and compare it with the baseline overlap.

**Mathematical acceptance:** reconcile connected labeled counts \(1,1,4,38,728,26704\) and connected unlabeled counts \(1,1,2,6,21,112\) through orders one to six. Independently verify uniqueness and coverage, not merely agreement with counts copied into the output.

**Verification:** test relabeled copies, distinct equal-degree graphs, digest determinism and reserialization. Reconstruct every graph from the manifest and rerun connectedness. Preserve generator logs and failure conditions.

**Done:** complete declared input population, independent reconciliation and canonical identity contract. **Typical failure:** silently extending the baseline beyond its supported order, or calling a heuristic spectrum/degree bucket an isomorphism class.

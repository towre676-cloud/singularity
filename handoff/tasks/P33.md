# P33 — Verify concrete coefficient certificates in a kernel

**Dependencies:** P07–P08 and P23, using P03 certificates. **Objective:** connect released table multiplicities to their mathematical definitions through an actual kernel-checked chain.

**Inspect first:** the real P07/P08 formal project; `src/singularity/certificates.py`; `results/certificates/spectral.json`, `binary_census.json`; `tests/test_analytics.py`: `CertificateTests`. No formal checker currently exists. Proposed `formal/Singularity/Certificates.lean` is new work; Python independent replay is valuable but is not kernel verification.

**Work:** define a finite enumeration of height tuples through the certificate bound, prove coverage and uniqueness, and prove the histogram accumulator computes the defined coefficients. Implement a checked import or proof-generating reflection route from `singularity.certificate/1`. Enumerated integer and rational arithmetic must be connected by proved correctness to the semantic coefficient definition. Declare trusted parsing, computation and compilation boundaries explicitly.

**Mathematical acceptance:** kernel-check both decisive graph-pair coefficient tables and their first-discrepancy factorizations, including equality at all lower volumes. Derive normalization and nested identities from P07/P08. A theorem that assumes the table's correctness, or verifies only a digest/parser, does not meet acceptance.

**Verification:** run the pinned clean build; mutate one graph edge and one decisive coefficient and show rejection. Retain successful proof artifacts, exact theorem names and input digests. No `sorry`, admitted project theorem or unexamined imported axiom may be described as complete verification.

**Done:** reproducible proof-producing pipeline tied to both released certificates. **Typical failure:** trusting an external Python success flag or replacing the difficult multiplicity proof with a parser theorem.

These are selected, unchanged files from the user's existing repositories. They are implementation references for the new roadmap; they do not mean that NX01–NX36 have already been implemented. The authoritative per-file record is `../provenance/COMPANION_SOURCES.json`. Each record identifies a repository, exact commit, original path, bundled path, byte count, SHA-256, and original Git blob identity. Sources were read at the pinned commits, not at a moving branch name.

## Read the existing implementation before writing a replacement

For NX01–NX02 read DynaComp `src/dynacomp/{enclosures,zonotope,uniform,robust,validated}.py`, then the corresponding tests and `docs/{UNIFORM,VALIDATED,FOREVER}.md`. For NX05–NX06 read PerfectJet `src/perfectjet/observatory/{model,experiments,histories}.py` and `docs/OBSERVATORY.md`. For NX03 and NX12 read PerfectPower `python/perfectpower/{planning,planning_certificate,budget_populations,future_states}.py` and `docs/COMPLETION_PLANNING_MONOGRAPH.md`. For NX08–NX11 and NX35 read DynaComp `src/dynacomp/{linear,metrics,stability,forever,realization,generating,binary64}.py` and the machine-generating monograph. For NX19–NX24 read PerfectPower's integer, Weil, recurrence and population modules. For NX31–NX33 read `python/perfectpower/{period_transport,period_observability,certified_period_transport,period_matrix_balls,differential_modules,differential_extensions,parameter_functions}.py`.

The scalar-observable machinery for NX31 already exists: `DifferentialModule.observable` delegates to `symmetry_quotients.PolynomialCurve.observable`, and `CurveFamily.observable` also computes a minimal universal scalar operator for its supplied observable. The supporting symmetry/local-curve source dependency chain is bundled. Reuse these APIs; NX31 should add target-specific validated transport, error contracts, branch handling and independent comparison rather than rebuild scalar extraction. The companion smoke script checks a module whose two targets have different orders, and a Legendre family whose extracted primitive operator is `[1] + [-4,8] D + [0,-4,4] D^2`. This is an existing computational capability, not a new formal theorem or proof of physical calibration.

Some names above may have closely related supporting files; the directory inventory and manifest are authoritative. Do not infer that all data-dependent entry points will execute solely because their source is bundled. Do not modify the snapshots to hide a missing dependency. Implement new NX code in the main project and record which mathematical and implementation ideas were reused.

## Reproduced checks in this package

The pinned PerfectJet Observatory subset passed all 54 included Observatory tests, including the HTTP session test, saved fixture replay, and adaptive branching example. The DynaComp selection passed 50 tests from eight targeted modules: zonotopes, uniform bounds, stability, thermal source, linear compilation, realization, forever bounds, and parametric analysis. PerfectPower passed six period-transport and seven validated matrix-ball tests. Its selected planning, planning-certificate, integral-lattice, integer-lifting, closest-integer, bounded-Pell, checked-Pell-orbit, Weil, recurrence, optimal-experiment, observable-machine and period modules imported successfully after relevant dependency inclusion.

An attempted wider PerfectPower test selection exposed an intentional packaging boundary: integer-projection code needs runtime assets located by `python/perfectpower/resources.py`; those assets are not bundled. The copied broad planning and query-service tests can also refer to unbundled catalogue modules and instances. The full PerfectPower test suite has **not** been claimed to pass in this subset. Bounded-Pell tests needing external assets were skipped. Additional files copied as transitive implementation references may have further optional imports that are not covered by the smoke checks.

Run `python verify_companions.py` from this directory to verify all pinned bytes against the manifest. Run `python verify_companions.py --smoke` to repeat the specifically documented passing tests. A complete source repository or release wheel must be acquired at the pinned commit before attempting omitted integrations. Installed numerical libraries are environment dependencies; they are not vendor-copied here.

## Historical and empirical boundaries

The historical-bridge table in `../provenance/HISTORICAL_BRIDGES.md` records which older work motivated each track. It is a synthesis of retrieved conversation material, not a replacement for original data or complete chat transcripts. WIND radar volumes, NFL player data, the old August V11 transport workspace, and any unbundled external benchmark matrices are **not** part of these source snapshots. Fetch and hash the appropriate datasets before making new empirical claims. An old reported synthetic improvement is not automatically an improvement on a real archive.

The DynaComp and PerfectJet pinned repository roots did not contain a standalone license file in the inspected tree. None has been invented. PerfectPower's actual `LICENSE` and `LICENSE-docs` files are included unchanged. Repository ownership and publication terms must be handled through the actual source repositories rather than an invented blanket license for this collection.

The full-current release, the companion snapshots, the proposed NX designs, old reported experiments, and new verified results are separate provenance classes. Keep that distinction when writing the monograph, release notes, acceptance ledger, or external benchmark claims.
